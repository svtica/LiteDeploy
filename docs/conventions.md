# LiteDeploy conventions

## Language

- Code, comments, file names, logs, commit messages and documentation: **English**.
- User interface: **English by default, French offered** (see *Localization*).

## Names

| Item | Rule | Example |
|---|---|---|
| Window (form) | `<Purpose>Form`, file named after the class | `ComputerListForm.cs`, `.Designer.cs`, `.resx` |
| Other class | noun, PascalCase, one public class per file | `PsExecLocator.cs` |
| Namespace | `LiteDeploy` for every type | |
| Control | camelCase + kind, unchanged once released (UI automation and translation keys use them) | `startDeploy`, `pingAllToolStripMenuItem` |
| PowerShell script | `Verb-Noun.ps1` with an approved verb, ASCII only | `Sign-Binaries.ps1`, `Measure-LiteDeploy.ps1` |
| Folders | `Classes/`, `Forms/`, `Properties/`, `Resources/`, `lang/`, `docs/`, `src/<library>/`, `tests/<project>.Tests/`, `tools/<area>/` | |

## File headers

Every C# file written by hand starts with:

```csharp
// -----------------------------------------------------------------------------
// LiteDeploy - part of LiteSuite. Released under The Unlicense (see LICENSE).
// File:    PsExecLocator.cs
// Author:  LiteDeploy contributors
// Date:    2026-11-11            (creation date of the file)
// Purpose: Finds PsExec: LiteDeploy folder first, then the tools folder of
//          LiteTask.
// -----------------------------------------------------------------------------
```

Files of `src/LiteSuite.Common` start with `// LiteSuite.Common - part of LiteSuite...`
and `// Author:  LiteSuite contributors`.

Files regenerated by Visual Studio (`Properties/Resources.Designer.cs`,
`Properties/Settings.Designer.cs`) keep their generated header.

Every PowerShell script starts with comment-based help (`.SYNOPSIS`,
`.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`); every workflow starts with a comment
block saying what it does and when it runs.

## Encoding

- C#, `.resx`, `.csproj`: UTF-8 with BOM (Visual Studio default).
- PowerShell: ASCII only (Windows PowerShell 5.1 reads a `.ps1` without BOM as ANSI).
- `lang/*.xml`: UTF-8.

## Localization

Same model as LiteTask: English texts live in the code and the designer files;
`lang/<language>.xml` (shipped next to `LiteDeploy.exe`) holds the translations:

```xml
<translations>
  <translation key="MainForm.startDeploy.Text">Démarrer le déploiement</translation>
  <translation key="MainForm.NothingToExecute">Vous n'avez choisi aucun fichier...</translation>
</translations>
```

- Window texts: `Localization.Apply(this)` right after `InitializeComponent()`
  translates the title (`<Form>.Text`) and every control, menu item, column
  header and dialog held in a field (`<Form>.<field>.Text`, `.Items.<n>` for
  combo boxes, `.Title` / `.Description` for dialogs).
- Texts in the code: `Localization.T("<Class>.<Name>", "English text")`, or
  `Localization.F(...)` with `{0}` placeholders; never build a sentence by
  concatenating translated pieces.
- Never test a displayed text: use a constant or a field (for example
  `ProcessReportsForm.DeploymentHost`, `LogEntry.Icon`).
- French texts follow the Quebec conventions: non-breaking space before
  `:`, `?`, `!` and `;`.
- Language: the user's choice in *App > Options* (Automatic follows the
  Windows display language), saved in `%LOCALAPPDATA%\LiteDeploy\settings.xml`;
  the `LITEDEPLOY_LANG` environment variable overrides it (tests).

A missing key falls back to the English text, so a partial translation never
breaks the interface.

## Shared library

Code that LiteTask needs too goes to `src/LiteSuite.Common` (namespace `LiteSuite`, C# 7.3,
`net48` and `net10.0-windows`, no reference to LiteDeploy or to Windows Forms), with its tests in
`tests/LiteSuite.Common.Tests`. See its README.

## Third-party tools

PsExec (Sysinternals) is the remote execution engine, as in LiteTask. It is
never redistributed: LiteDeploy uses the copy next to `LiteDeploy.exe` or the
`PsExec64.exe` that LiteTask extracts to its tools folder.
